# Ralph 장시간 실행 프롬프트 점검

점검일: 2026-09-21. 이 문서는 실행 준비 점검이며 7시간 실행 결과가 아니다.

## 현재 폴더에서 확인한 상태

- 루트의 `AGENTS.md`, `goal.md`, `prd.md`, `task.md`, `progress.md`, `.gitignore`, `.env.example`과 `docs/gs25-store-manager-training-map.md`를 확인했다.
- `.env.local`은 파일 존재와 Git 제외 여부만 확인하며 내용은 읽거나 출력하지 않는다. `.git`은 상태와 추적 파일 목록만 확인한다.
- 앱 소스, `package.json`, 테스트, 의존성 설치 폴더, 별도의 Ralph 실행 스크립트나 실행 제한 설정은 아직 없다. 따라서 이번 점검으로 앱 빌드 성공이나 실제 Ralph 실행 시간을 입증할 수 없다.
- 이미 수정된 문서와 추적되지 않은 `docs/`가 있었으므로 기존 내용을 유지하며 필요한 부분만 보강한다.

## 발견한 문제와 수정

| 기존 문제 | 수정 |
|---|---|
| 목표 시간이 없고 기본 P0 완료 즉시 종료 | 유효 작업 420분 목표, 7–10시간 계획 범위, Task 16 최종 종료 조건 |
| 실제 구현이 빨리 끝나면 후속 작업이 모호함 | 같은 P0 흐름의 실패 복구·데이터 일관성·사용성·릴리스 검증을 Tasks 10–16으로 명시 |
| 작업 간 의존성을 문맥으로 추정해야 함 | 모든 작업에 명시적 `Depends on` 추가 |
| 현재 사용할 수 없는 `superpowers` 스킬 필수 요구 | 사용 가능한 도구로 순차 실행하도록 변경 |
| 규칙 추가와 경영주의 체크리스트 편집 작업 누락 | Tasks 3, 8에 구현과 검증 추가, Task 13에서 연결 검증 |
| 실 Gemini 확인과 회귀 검증이 혼동될 수 있음 | 자동 회귀는 강제 데모 모드, 기존 키를 이용한 제한된 실제 API 확인은 사전 승인 |
| 중단·컨텍스트 교체 후 재개 기준 부족 | 타임스탬프, 실제 작업 시간, 실패 횟수, 다음 체크박스와 명령 기록 |
| 동일 실패가 모든 독립 작업을 막을 수 있음 | 동일 원인 3회 실패 시 해당 작업 중단, 가능한 독립 작업만 계속 |

## 계획된 작업량

| 구간 | 결과물 | 계획 시간 |
|---|---|---|
| Tasks 1–9 | 기반, 데이터, 경영주 편집, 시뮬레이션, Q&A, 체크리스트, 대시보드 | 3–4시간 |
| Tasks 10–15 | 저장·행동 로그·AI 오류·화면 간 일관성·접근성·프로덕션 브라우저 검증 | 3–5시간 |
| Task 16 | 잔여 결함 검토, 시연 문서, 최종 검증과 증거 정리 | 약 1시간 |

합계 7–10시간은 계획용 추정이며 실제 소요 시간 보장이 아니다. 에이전트 속도, 설치와 테스트 환경, 오류 발생, 도구·사용량 제한에 따라 달라진다. 시간만 채우기 위한 대기, 같은 성공 테스트 반복, 의미 없는 UI 변경은 금지한다. 모든 항목이 일찍 끝나면 실제 시간을 기록하고 `completed-before-duration-target`으로 종료한다. 7시간이 지나도 필수 검증이 남아 있으면 계속 진행한다.

## 최종 검토에서 사용할 실패 조건 표

이미 검증한 항목은 증거를 재사용한다. 이 표 때문에 같은 테스트를 불필요하게 추가하거나 반복하지 않는다.

| 영역 | 확인할 조건 | 기대 결과 |
|---|---|---|
| 저장 | 손상 JSON, 스키마 불일치, 읽기/쓰기 거부, 용량 초과 | 안전한 복구 또는 저장되지 않았음을 알리는 상태 |
| 규칙 | 저장 후 새 질문/새 세션, 진행 중 세션, 새 규칙 추가 | 새 요청은 최신 버전, 진행 중 세션은 기존 스냅샷 |
| 행동 | 조회 전 답변, 조회 후 답변, 엉뚱한 상품 조회, 중복 제출 | 순서와 대상이 반영된 결정론적 판정, 중복 집계 없음 |
| AI | 타임아웃, 할당량 오류, 잘못된 형식, 모순된 가격 | 제한된 대기 후 데모 전환, 고정 사실·판정 변경 없음 |
| Q&A | 관련 근거 없음, 우연한 키워드 일치, 규칙 추가 후 재질문 | 근거 없는 확답 금지, 과거 기록 보존, 새 근거 표시 |
| 체크리스트 | 경영주 추가/편집, 세 상태 전환, 새로고침 | 안정된 ID, 진행 상태 유지, 정확한 집계 |
| 초기화 | 취소, 확인, 초기화 후 재시연 | 취소 시 보존, 확인 시 앱 데이터만 초기화 |
| 화면 | 모바일/데스크톱, 키보드, 요청 대기/실패, 직접 경로 진입 | 완료 가능한 흐름, 접근 가능한 컨트롤, 복구 방법 표시 |
| 릴리스 | 프로덕션 빌드 서버에서 전체 E2E와 시연 | 개발 서버에만 의존하지 않는 재현 가능한 데모 |

## 실행 전 확인

1. 실제 실행에 사용할 `goal.md`의 전체 `text` 블록을 복사한다. 제출 전 원문과 실제 제출 문구가 일치하는지 확인하고, 다르면 `progress.md`에 이유를 남긴다.
2. 실행 호스트의 시간·사용량·토큰 제한과 재개 방식을 확인한다. 폴더에는 그 제한을 바꾸는 설정이 없으며, 이 문서 수정으로 실행 시간이 늘어나지 않는다. 임의의 Ralph CLI 옵션이나 존재하지 않는 자동 재시작 기능을 가정하지 않는다.
3. 패키지 설치와 브라우저 실행에 필요한 도구/네트워크 권한을 확인한다. 권한 요청이 실제로 발생하면 증거를 남기고, 승인되지 않은 우회는 하지 않는다.
4. 자동 회귀와 해당 빌드는 `AI_DEMO_MODE=true`로 검증한다. 기존 키가 있으면 별도 실행에서 제한된 실제 Gemini 확인을 수행하고 회귀 검증은 데모 모드로 복귀한다. 실제 Gemini 호출·Git 게시·배포는 사전 승인되었으므로 재승인을 요청하지 않는다. 로컬 검증 후 설정에서 확인한 저장소·브랜치·배포 대상에 게시하고 원격 커밋, 배포 상태와 URL, 실제 화면을 확인한다. 키 값은 기록하거나 Git에 넣지 않으며 필요한 서버 환경변수만 확인된 배포 대상에 설정한다. 누락된 접속 정보나 대상은 구체적인 차단 사유로 기록한다. 이 지침은 호스트 권한 정책을 변경하지 않는다.
5. 첫 구현 작업을 시작할 때만 시간 기록을 시작한다. 이번 문서 편집 시간을 구현 실행에 합산하지 않는다.
6. 장시간 연속 실행이 호스트에서 중단되면 마지막 체크포인트부터 재개한다. 무인 7시간 실행 성공은 실제 세션 기록으로만 보고한다.
