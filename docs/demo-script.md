# 첫날.zip 시연

## 준비

Node.js 24 이상에서 `npm ci`, `npx playwright install chromium`을 실행한다. 실제 Gemini 키는 `.env.local`의 `GEMINI_API_KEY`에만 저장한다. 재현 가능한 시연은 PowerShell에서 `$env:AI_DEMO_MODE='true'`를 지정한 뒤 `npm run build`, `npm run start`로 시작한다. `http://localhost:3000`을 새 브라우저 컨텍스트에서 연다.

실제 응답 시연은 서버 실행 전에 `$env:AI_DEMO_MODE='false'`를 지정한다. SDK deadline은 15초, 앱의 취소 시점은 12초이며 실패 시 데모 응답임을 표시한다. 외부 연결 여부는 UI의 `Gemini 표현` 또는 `데모 모드`로 구분한다. 역할 표시의 데모 모드는 인증 없는 역할 전환을 뜻한다.

## 같은 브라우저에서 진행

1. **경영주로 시작** → **대시보드** → **데모 데이터 초기화**. 취소하면 기록이 보존되고 **초기화하기**를 누르면 기본값으로 돌아간다.
2. **매장 매뉴얼**에서 행사 규칙 내용을 `POS 조회 후 동일 상품 행사 조건을 천천히 안내해요.`로 저장한다. 버전이 v2로 바뀐다. **업무 관리**에서는 이름·설명·분류를 수정하거나 업무 항목을 추가할 수 있다. 아래 숫자 시연은 기본 네 항목을 유지한다.
3. **스토어 매니저로 전환** → **응대 연습** → **연습 시작**. POS를 조회하지 않고 행사 적용, 총액 `4500`, 고객에게 할 말을 입력해 결과를 본다. POS 미조회, 확인 전 확정 안내 있음, 마지막 안내 다시 확인 필요가 나타난다.
4. **같은 상황 다시 연습** → **캔커피 A 조회**. 단가 1,500원과 같은 상품 세 개 3,000원 조건을 확인한다. 행사 적용, 총액 `3000`으로 답한다. 확인한 절차와 첫 시도 비교를 확인한다. 재도전은 별도의 완료 시도로 기록된다.
5. **매장 Q&A**에서 행사 규칙 버튼을 누른다. 새 문구와 v2 근거, 구조화된 행사 금액을 확인한다. `택배 접수`를 질문하면 경영주 확인 필요로 남는다.
6. **체크리스트**에서 입고 상품 확인을 **완료**, 소비기한 확인을 **경영주 확인 필요**로 선택한다. 새로고침 후에도 유지된다.
7. **경영주로 전환** → **대시보드**. 완료 연습 **2**, 업무 **1/4**, 질문 **2**, 확인 필요 **2**를 확인한다. 확인 필요는 미해결 질문 1개와 업무 1개이며, 직원 점수나 순위가 아니다.
8. **매장 매뉴얼**에 제목 `택배 접수`, 내용 `가상 매장은 택배 접수를 하지 않아요.`, 분류 `합성 안내`, 예외 `추가 문의는 경영주에게 확인해요.`로 규칙을 추가한다. 스토어 매니저의 Q&A에서 새 규칙 버튼을 누르면 v1 근거로 답하고, 이전 미해결 기록은 바뀌지 않는다. 누적 질문은 **3**, 확인 필요는 여전히 **2**다.
9. 선택적으로 **다른 상품을 섞는 상황 연습**에서 POS 조회 → **경영주 확인 요청** → **경영주에게 확인 후 안내**로 답한다. 역할극 확인 요청은 실제 업무 요청 수에 포함되지 않는다.
10. 대시보드 초기화 후 연습 0, 질문 0, 업무 0/4, 확인 필요 0으로 돌아오는지 확인한다.

## 검증과 한계

- 자동 재현: `npm test` → 강제 데모 `npm run build` → `npm run test:e2e`. E2E는 자체 프로덕션 서버(3100), 별도 컨텍스트, 두 화면 크기에서 수행한다.
- 별도 실호출: `AI_DEMO_MODE=false` 서버를 3101에서 띄우고 `node scripts/live-smoke.mjs`를 실행한다. 고객·코치·Q&A의 실제 모드와 근거를 확인하며 키·원문 요청은 출력하지 않는다.
- 합성 데이터의 가격과 행사 계산은 `src/domain`의 구조화된 값이 결정한다. 매뉴얼 문구 편집이 상품 가격이나 행사 계산식을 바꾸지는 않는다.
- 진행 중 연습은 시작할 때의 규칙 사본을, 새로운 연습과 Q&A는 최신 규칙을 사용한다. 자유롭게 쓴 고객 응대 문장의 뜻을 LLM으로 채점하지 않고 선택한 안내 유형과 금액을 평가한다.
- 브라우저 로컬 데모이며 계정 인증, 실제 매장 연동, 여러 기기·탭 동기화는 없다. 저장 공간이 없으면 임시 상태로 표시한다.
- Q&A 검색은 보수적이다. 근거가 모호하면 경영주에게 확인하도록 남긴다. 과거 미해결 기록을 닫는 업무 기능은 P0 범위에 없다.
- 최종 확인 결과는 `verification-matrix.md`, 시간·실패·재개 기록은 `../progress.md`에 남긴다.
